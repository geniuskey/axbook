# AXBook 집필 개요 (편집 기준서)

## 책의 문제의식
대기업 제조업(전자·반도체·디스플레이·자동차부품·화학·기계 등)의 현실:
- **레거시 파일**: 공유 드라이브·개인 PC·NAS에 흩어진 엑셀/PPT/PDF/한글(HWP) 문서, `최종_v3_수정_진짜최종.xlsx`, 버전 관리 없음, 매크로에 숨은 로직.
- **이메일로 오가는 정의되지 않은 데이터**: 메일 본문·첨부에만 있는 결정·수치·합의, 스레드가 갈라지고 참조자가 바뀌며 맥락이 사라짐. 담당자가 떠나면 지식도 떠남.
- **이슈마다 달라지는 프로세스와 산출물**: 품질 이슈·고객 클레임·설비 고장이 생길 때마다 대응 절차와 보고서 양식이 새로 만들어짐. 같은 종류의 문제인데 매번 다른 산출물.
- **팀·파트마다 다른 포맷과 언어**: 같은 불량을 다른 이름·코드로 부르고, 단위·날짜·ID 체계가 다르며, 같은 KPI를 다르게 계산.
- **국제표준이 닿지 않는 회색지대**: ISO 9001·IATF 16949 같은 표준이 덮는 영역 밖(사내 협업, 임시 TF, 부서 간 인계)에서는 프로세스 자체가 무너짐.
- 시대 배경(2026): 생성형 AI·에이전트·추론 모델의 급격한 발전, DX를 하던 조직이 AX로 넘어가야 하는 압력. "AI를 붙이면 된다"가 아니라 **데이터·프로세스·언어·사람**을 먼저 정리해야 AI가 효과를 낸다는 것이 이 책의 핵심 주장.

## 독자
대기업 제조업 실무자와 리더: 공정/품질/설비/생산관리/구매/연구개발 엔지니어, 기획·혁신 담당, IT·데이터 담당, 팀장·파트장. 코딩 지식을 전제하지 않는다.

## 절대 규칙
- **실제 기업을 사례의 주인공으로 쓰지 않는다.** 특정 회사를 겨냥한 듯한 묘사도 피한다. 사례는 "A사(글로벌 전자부품 제조사)", "B사(자동차 부품)", "C사(정밀화학)" 같은 가상 회사로 일반화한다.
- 실명 기업은 공개적으로 널리 알려진 사실만, 여러 회사 중 하나로 짧게(예: WEF 글로벌 등대 네트워크(Global Lighthouse Network)에는 여러 나라의 제조사가 선정되어 있다). 확신 없는 회사별 수치·주장은 쓰지 않는다.
- 숫자는 (a) 널리 알려진 출처를 밝히거나(기관·보고서·연도, 확신이 있을 때만), (b) "예시 수치"라고 명시한다. 지어낸 통계를 사실처럼 쓰지 않는다.
- 표준·규제·프레임워크 명칭은 정확하게. 세부 조항 번호는 확신이 없으면 쓰지 않는다.

## 장 구성 (slug · 제목 · 요지 · 권장 인터랙티브)

01 `why` 왜 지금 AX인가
- 디지털화(digitization)–디지털라이제이션(digitalization)–DX–AX 구분. 자동화 vs 증강 vs 자율.
- AX의 정의: AI를 업무의 기본 구성요소로 재설계하는 것. 도구 도입이 아니라 일하는 방식의 전환.
- 왜 많은 전환이 "파일럿 연옥(pilot purgatory)"에 빠지는가: 데이터 부재, 프로세스 비표준, 현업 소외, 측정 부재, 보안 우려.
- AX의 4개 기반: 데이터·프로세스·공통 언어(표준)·사람/조직 + 그 위의 AI. "AI는 정리된 조직을 증폭하고, 혼란스러운 조직도 증폭한다."
- 인터랙티브: ① AX 성숙도 자가진단(6~8개 차원 슬라이더 → 레이더 차트 + 단계 판정 + 가장 약한 고리 표시; AX.store 저장해서 14장과 공유: key "assessment"), ② "AI는 증폭기" 시뮬레이터(데이터 품질×프로세스 표준화 → AI 도입 효과가 +/− 어떻게 나오는지 곡선), ③ 파일럿 → 확산 깔때기(파일럿 수, 단계별 통과율 → 실제 확산 수).

02 `legacy` 레거시의 해부
- 다크 데이터, 데이터 사일로, 정보의 실제 거주지(메일, 메신저, 개인 PC, 공유 폴더, 엑셀, PPT 보고서, 종이·스캔, 사람 머릿속).
- 엑셀이 시스템이 되는 과정(EUC, End-User Computing)과 위험(수식 오류, 매크로, 버전).
- 이메일 스레드 해부: 결정·수치·기한·담당자·근거가 어디에 묻혀 있는지 메일 목업에 하이라이트.
- 보고서용 PPT의 문제: 데이터가 아닌 "그림"으로 저장됨, 재사용 불가.
- 정보 인벤토리 만드는 법(어디에, 누가, 얼마나 자주, 어떤 형식, 누가 쓰는가), 정보 가치 vs 접근성.
- 인터랙티브: ① 정보 거주지 지도(우리 팀 정보가 어디에 몇 %인지 슬라이더 → "AI-준비 비율"과 "검색 소요 시간" 추정), ② 메일 스레드 구조화 실습(버튼으로 하이라이트 단계별: 결정/수치/기한/담당/근거 추출 → 구조화된 레코드 표로 변환), ③ 파일 버전 혼돈 시뮬레이터(사람 수·공유 방식에 따라 버전 분기 수가 늘어나는 모델) 또는 "검색 비용" 계산기(인원×일일 검색 시간×연간 비용).

03 `process` 프로세스 부채
- 프로세스 부채(process debt)의 정의: 임시방편 절차가 쌓여 생긴 변동성. 이슈마다 다른 대응, 다른 산출물.
- 표준이 있는 곳(ISO 9001, IATF 16949, 8D, CAPA, FMEA)과 없는 곳(부서 간 인계, 임시 TF, 고객 대응 초기, 내부 보고).
- 프로세스 마이닝: 이벤트 로그(케이스 ID, 활동, 타임스탬프)로 실제 흐름을 복원. 변종(variant), 재작업 루프, 병목.
- 표준 대응 흐름 + 표준 산출물 템플릿(이슈 카드), "같은 문제는 같은 양식으로".
- SIPOC, RACI, 프로세스 오너 개념.
- 인터랙티브: ① 프로세스 마이닝 체험(가상의 이슈 대응 이벤트 로그 생성 → 변종 수, 평균 리드타임, 재작업률; '표준화 수준' 슬라이더로 변종 수렴 확인; 흐름도를 canvas/SVG로), ② 산출물 폭발 계산기(이슈 유형 수×팀 수×양식 변형 → 서로 다른 산출물 양식 수, 통합 템플릿 적용 시 감소), ③ 8D 단계 인터랙티브(D0~D8 클릭하면 각 단계의 산출물·데이터·AI 지원 포인트 표시).

04 `semantics` 공통 언어: 표준과 온톨로지
- 같은 것을 다르게 부르는 문제: 불량명, 설비명, 부품번호, 고객명, 단위, 날짜, 시간대, LOT ID.
- 기준정보(MDM, Master Data Management), 비즈니스 용어 사전(glossary), 코드 체계, 데이터 사전(data dictionary).
- 계층 모델: ISA-95/IEC 62264(Enterprise–Site–Area–Work Center–Work Unit, Level 0~4), 자산 관리 셸(AAS, IEC 63278), OPC UA 정보 모델.
- 온톨로지와 지식 그래프의 입문: 개념–관계–속성. 택소노미 vs 온톨로지.
- 점대점 매핑 n(n−1)/2 vs 정준 데이터 모델(canonical model) 2n. 
- 인터랙티브: ① 이름 매핑 실습(같은 불량을 12가지로 부르는 목록 → 정준 코드로 매핑하는 클릭 실습, 정확도 표시), ② 매핑 수 비교 차트(시스템/팀 수 슬라이더 → 점대점 vs 허브 매핑 수), ③ ISA-95 계층 탐색기(클릭하면 각 레벨의 시스템·데이터 예시·주기).

05 `foundation` 데이터 기반과 거버넌스
- 데이터 품질 차원(완전성, 정확성, 일관성, 적시성, 유일성, 유효성) — DAMA-DMBOK, ISO 8000 언급.
- 데이터 오너·스튜어드·커스터디언 역할, 데이터 계약(data contract), 리니지(lineage), 카탈로그.
- 아키텍처: 데이터 레이크/웨어하우스/레이크하우스, 메달리온(브론즈·실버·골드), 데이터 메시 개념(도메인 소유).
- "AI-ready data" 체크리스트.
- 인터랙티브: ① 데이터 품질 스코어카드(가상 테이블에 오류 주입 슬라이더 → 차원별 점수와 실제 표 하이라이트), ② 메달리온 파이프라인 단계별 변환 체험(원본 행들이 정제·조인·집계되는 과정), ③ 품질이 AI 성능에 미치는 영향(라벨 노이즈 % → 모델 정확도 곡선, 간단 모델).

06 `knowledge` 문서를 지식으로: RAG와 지식 그래프
- 비정형 문서 처리: 파싱(PDF, PPT, 엑셀, HWP, 스캔 OCR), 표·그림 처리, 메타데이터.
- 청킹(고정 길이/구조 기반/의미 기반), 임베딩, 벡터 검색과 키워드 검색(BM25)의 하이브리드, 재순위화(reranking).
- RAG 파이프라인, 출처 표시(citation), 권한 기반 검색(ACL), 최신성, 평가(정확도·근거성·검색 재현율).
- GraphRAG/지식 그래프, 언제 무엇을 쓰나. 롱 컨텍스트와의 관계.
- 인터랙티브: ① 미니 RAG(브라우저 안의 가상 사내 문서 10~15개(가상 품질 보고서·설비 매뉴얼·회의록) → 질문 입력 → 키워드/TF-IDF 점수로 상위 청크 표시 → 답에 쓰일 근거 하이라이트), ② 청크 크기 실험(청크 크기 슬라이더 → 검색 정밀도/맥락 손실 트레이드오프 곡선), ③ 권한 필터 시연(사용자 역할 선택 → 검색 결과가 달라짐).

07 `usecases` 유스케이스 발굴과 우선순위
- 가치사슬 지도: R&D/설계, 구매·SCM, 생산, 품질, 설비, 물류, 영업·고객, 경영지원 별 대표 AI 유스케이스.
- 유스케이스 유형: 검색·요약, 작성·변환, 분류·추출, 예측, 최적화, 이상 탐지, 에이전트형 자동화.
- 가치–실현성 매트릭스, 데이터 준비도, 리스크. 퀵윈 vs 전략 과제.
- ROI 계산: 절감 시간×인원×채택률 − 비용, 품질 비용(COPQ) 감소, 리드타임. 측정 가능한 KPI 정의.
- 유스케이스 캔버스 양식.
- 인터랙티브: ① 유스케이스 포트폴리오 매트릭스(12개 가상 유스케이스를 점수 조정 → 2×2 산점도에 배치, 사분면 표시), ② ROI 계산기(인원, 업무시간 비중, 절감률, 채택률 곡선, 구축·운영비 → 손익분기·3년 NPV 차트), ③ 업무 분해기(업무를 작업 단위로 나누고 각 작업의 AI 적합도를 고르면 자동화 가능 비중 표시).

08 `agents` 코파일럿에서 에이전트로
- LLM의 기본 동작(아주 짧게), 프롬프트, 컨텍스트, 도구 사용(tool use), MCP 같은 표준 연결, 워크플로 vs 에이전트.
- 자율성 단계(L0 수동 ~ L4/5 자율), 사람의 승인 지점(human-in-the-loop / on-the-loop).
- 다단계 오류 누적: 단계별 정확도 p^n, 검증 단계 삽입 효과.
- 제조 시나리오: 8D 보고서 초안 에이전트, 설비 알람 트리아지, 구매 견적 비교, 설계 변경(ECN) 영향 분석.
- 에이전트 설계 원칙: 좁게 시작, 도구 권한 최소화, 로그·감사, 평가 세트.
- 인터랙티브: ① 오류 누적 계산기(단계 수, 단계 정확도, 검증 체크포인트 수/검출률 → 최종 성공률 차트), ② 자율성 단계 슬라이더(8D 업무 각 단계에서 AI/사람 역할이 바뀌는 표), ③ 에이전트 실행 트레이스 재생(가상의 설비 알람 → 생각/도구 호출/결과 단계가 하나씩 나타나는 스텝 재생, 승인 버튼).

09 `shopfloor` 현장 AI: 설비·공정·품질
- OT/IT 융합, 데이터 원천(PLC, SCADA, MES, 설비 로그, 계측기, 비전), 수집 주기, OPC UA, 엣지.
- SPC(관리도, Cpk)와 ML 이상 탐지의 관계, 불균형 데이터, 오탐/미탐 비용.
- 예지 보전(PdM): 열화 곡선, 잔여 수명(RUL), 보전 전략 비교(사후/예방/예지).
- 비전 검사, 가상 계측(VM), 공정 레시피 최적화, 디지털 트윈 개념.
- 현장 AI가 실패하는 이유: 데이터 라벨 부족, 드리프트, 현장 신뢰, 운영(MLOps).
- 인터랙티브: ① 이상 탐지 임계값(정상/불량 분포, 불량률 슬라이더, 임계값 → 혼동행렬·정밀도·재현율·비용), ② 관리도 시뮬레이터(공정 평균 이동/산포 증가 주입 → 관리 한계 이탈과 Western Electric 규칙 탐지), ③ 보전 전략 비용 비교(고장률·예측 정확도·리드타임 → 연간 비용 막대).

10 `governance` AI 거버넌스·보안·리스크
- 왜 거버넌스가 속도를 높이는가(가드레일). 섀도 AI(개인 계정으로 외부 AI에 사내 문서 붙여넣기).
- 기술 유출·영업비밀·국가핵심기술(산업기술보호법 등 일반 언급), 개인정보.
- 프레임워크: ISO/IEC 42001(AI 경영시스템), ISO/IEC 23894(AI 리스크 관리), NIST AI RMF 1.0(Govern, Map, Measure, Manage), EU AI Act(위험 기반 4단계: 금지/고위험/제한적(투명성)/최소), 한국 AI 기본법(2026년 시행 예정/시행 — 확신 범위 내에서만 일반적으로 언급).
- 데이터 등급 분류와 모델 선택(외부 API/사내 호스팅/온프레미스), 프롬프트 주입, 환각, 평가·모니터링, 책임(RACI), 모델 카드.
- 인터랙티브: ① 유스케이스 리스크 분류 마법사(질문 6~8개 → 위험 등급, 필요한 통제 목록), ② 데이터 등급 × 배포 방식 허용 매트릭스(클릭으로 셀 상태 확인), ③ 환각/검증 시뮬레이터(근거 제공 여부·검증 단계 → 잘못된 답이 사용자에게 도달하는 확률).

11 `people` 사람과 조직: 변화 관리
- 운영 모델: 중앙 CoE, 허브-스포크, 연합형. 장단점.
- 역할: 도메인 전문가, 프로덕트 오너, 데이터 엔지니어, AI 엔지니어, 데이터 스튜어드, AX 챔피언. "현업이 주인"이어야 하는 이유.
- 역량 체계(전 직원 AI 리터러시 → 파워유저 → 빌더 → 전문가).
- 변화 관리: ADKAR, 코터 8단계(간략), 저항의 원인(일자리 불안, 추가 업무, 신뢰), 인센티브와 KPI, 성공 공유.
- 확산(Bass 확산 모델), 초기 사용자·챔피언의 역할.
- 인터랙티브: ① 채택 확산 시뮬레이터(Bass 모델 p, q + 교육·챔피언·UX 마찰 슬라이더 → 채택 곡선), ② 운영 모델 선택기(조직 규모·사업 다양성·데이터 성숙도 → 추천 모델과 이유), ③ 역량 피라미드(인원 비율 입력 → 교육 필요량 계산).

12 `roadmap` 단계별 로드맵: 레거시에서 AX까지
- 6단계: 가시화(인벤토리) → 표준화(용어·양식·프로세스) → 디지털화(문서/메일 → 시스템·구조화) → 데이터화(통합·품질·거버넌스) → 지능화(AI 유스케이스) → 자율화(에이전트·폐루프).
- 각 단계의 산출물, 진입/졸업 기준, 흔한 함정, 기간 감각(예시).
- 등대(lighthouse) 프로젝트 → 확산, "얇은 수직 슬라이스" 전략: 한 업무를 끝까지 관통.
- 30-60-90일 계획, 18개월 로드맵 예시, 투자 배분(기반 vs 유스케이스).
- 인터랙티브: ① 로드맵 빌더(이니셔티브 카드 15개를 분기별로 배치 → 의존성 위반 경고(예: RAG 전에 문서 인벤토리·권한 정리), 간트 차트), ② 단계 판정기(체크리스트 체크 → 현재 단계와 다음 졸업 조건), ③ 투자 배분 슬라이더(기반 vs 유스케이스 비중 → 시간에 따른 누적 가치 곡선: 기반 없이 하면 초기엔 빠르지만 정체).

13 `cases` 사례로 보는 AX
- 가상 회사 사례 4~5개, 각 사례를 "레거시 방식 → 무엇이 문제였나 → AX 방식(데이터·프로세스·AI) → 결과(예시 수치) → 교훈"으로:
  1) A사 고객 품질 클레임 대응(메일·엑셀 기반 → 이슈 카드 + 과거 유사사례 RAG + 8D 초안)
  2) B사 설비 알람 대응·보전(작업일지 엑셀 → 표준 고장코드 + 예지 보전 + 정비 이력 검색)
  3) C사 설계 변경(ECN) 영향 분석(메일 결재 → BOM·문서 연결 지식 그래프)
  4) D사 공급망 이슈(부품 단종·납기 지연 공지 메일 → 자동 분류·영향 부품 매칭)
  5) E사 사내 지식 검색(퇴직자 지식 손실 → 전문가 인터뷰·문서 RAG)
- 공개적으로 알려진 업계 흐름: WEF 등대공장, 산업용 AI 플랫폼 트렌드 — 일반적으로만.
- 인터랙티브: ① "이슈 발생!" 롤플레이(가상 클레임 이벤트, 레거시/AX 방식 선택해 단계 진행 → 소요 시간, 관련 인원, 재발 여부 비교 타임라인), ② 사례별 전후 지표 비교 막대(사례 선택 seg), ③ 교훈 매칭 퀴즈 스타일 카드.

14 `playbook` AX 플레이북: 우리 팀 설계하기
- 1장 자가진단 결과(AX.store "assessment")를 불러오거나 새로 입력.
- 단계: 팀 프로필 → 고통점(pain point) 선택 → 정보 거주지 → 첫 유스케이스 선택 → 자동 생성되는 90일 계획(주차별), 유스케이스 캔버스, 성공 지표, 리스크 체크, 이해관계자.
- 인쇄/복사 가능한 결과(텍스트 복사 버튼, window.print).
- 짧은 본문: 플레이북 사용법, 리더를 위한 질문 리스트, 경영진 보고용 한 장 요약 템플릿.

15 `glossary` 용어집 & 종합 퀴즈
- 용어 120개 이상(한국어 + 영어 + 짧은 정의 + 관련 장 링크), 검색 필터.
- 종합 퀴즈 25~30문항, 점수 표시.
- sensorbook 용어집 구조와 같게: `.gl-search`, `.gl-list`, `.gl-item`.

## 공통 형식
- 장마다 6~9개 섹션(h2), 2~4개 SVG 그림(“그림 N-k.” 캡션), 표 1개 이상, 인터랙티브 3개 내외(각각 `.sim`, 태그 `INTERACTIVE`), 콜아웃 몇 개, `핵심 정리`, `확인 퀴즈` 5~6문항.
- 각 장 머리에 lead와 학습 목표(objectives) 3~4개.
- 다른 장을 참조할 때는 `<a href="legacy.html">2장</a>`처럼 링크.
- 분량 감: HTML 700~1100줄 정도(인터랙티브 스크립트 포함). 본문은 실무자가 읽을 수 있는 구체적 문장으로. 일반론 나열이 아니라 "현장에서는 이렇게 보인다 → 이렇게 고친다"를 계속 보여 준다.

## 추가 장 (2026-10)
현재 번호: 12 `goals`, 13 `reporting`, 14 `system`, 15 `experiments`, 16 `roadmap`, 17 `cases`, 18 `playbook`, 19 `questions`, 20 `glossary`. (위 장 구성의 12~15번 roadmap·cases·playbook·glossary는 각각 16·17·18·20번이다.)

15 `experiments` 실험하는 조직의 AX: 맥락 있는 데이터와 FDE
- 같은 DB·같은 양식, 다른 기준(수율 정의·측정 방법·장비). 설비 데이터와 실험 데이터의 차이.
- 실험 조직의 AX 정의: 기준을 고정하지 않고 선언·버전 관리해 다시 찾고, 올바르게 비교하고, 재사용하게 한다. "자유롭게 실험하되, 기록은 표준으로."
- AI 가독성 사다리(존재–접근–기계 판독–자기 서술–맥락 연결–AI 활용 가능), FAIR 원칙과의 관계.
- 기준 레지스트리(ID@버전), 실험 카드, AI로 입력 부담 줄이기.
- 상위 조직이 하위 조직 AX 성과를 신뢰하는 증거 사다리(주장–산출물–사용 기록–전후 비교–비교군–독립 확인), 굿하트의 법칙.
- FDE(Forward Deployed Engineer): 상주 → 함께 만들기 → 일반화·환류 → 졸업, 성과는 떠난 뒤로 잰다.
- 인터랙티브: AI 가독성 점검기, 기준 드리프트 시뮬레이터, 성과 신뢰도 점검기.

19 `questions` AX에 대한 정직한 질문들
- 유행인가(6시그마와 비교, 캠페인 vs 체질), 기간(생산성 J-커브), top-down/bottom-up 역할 분담, 실무자 자기 업무 개선의 "번역", 표준화와 창의성(탐색과 활용, 좁은 허리, 도전자 경로), 보안의 적정선(10장 파레토 프런티어로 연결), 숙련자 병목(대기열), AX 이후 사람의 역할과 인재상, 강의 중심 교육의 한계.
- 인터랙티브: 캠페인형/체질 전환형 진단, J-커브와 중단 시점, 숙련자 병목 시뮬레이터.

10 `governance` 보강: "보안과 AX의 적정선" 섹션 — 보안 정책 선택지를 위험–가치 평면에 놓고 파레토 프런티어로 비효율 선택지(종종 전면 금지)를 걸러 낸 뒤, 프런티어 위의 점은 사업 책임자와 보안이 위험 성향에 따라 함께 고른다.

13 `reporting` AX 시대의 보고와 평가
- 윗선의 질문 하나가 계층을 내려가며 복제·사전 점검·수정 전파로 증폭되는 구조(푸시형 vs 풀형).
- 보고의 목적(상태 공유·위험 경보·결정 요청·성과 인정)별 형태: 대시보드·직접 질의, 예외 알림, 결정 메모, 성과 레지스트리. "보고서는 업무의 부산물".
- 성과 인정을 위한 문서 작업의 적정선: 보고 예산, 수정 상한, 양식 동결, 결정 있는 회의만.
- 보고받고 평가하는 상위·스태프 조직의 AX, 보고 부담 지표, 평가자의 자격.
- 팀·개인 단위 AX는 디지털화·표준화·자동화·연결·AI 활용의 언어로. 금액 환산은 사업부 이상.
- 증거 기반 목표 평가 6원칙. 특정 실명 기업의 조직 문화는 언급하지 않는다.
- 데일리·주간 보고가 우선순위 변경 통로가 될 때의 우선순위 부채, 팀 목표·작업의 공유 보드 운영(동시 진행 상한, 내려놓을 일 명시).
- 인터랙티브: 보고 증폭 계산기, 보고 형태 분류기, 우선순위 변동 시뮬레이터, 평가하는 조직의 AX 자가진단.

14 `system` 전체를 보는 AX: 인터페이스, 가치 실현, 투자
- 팀별 목표 달성에도 전체 리드타임이 그대로인 이유: 흐름 효율(처리 vs 대기·재작업).
- 콘웨이의 법칙, 팀 간 산출물 계약(팀 API), 계층별 인터페이스 책임(팀 안 / 실: 팀 간 계약 / 사업부: 시스템 API / 플랫폼 조직: 표준). API가 없을 때의 과도기 전략.
- 해방된 용량이 금액이 되는 경로와 가치 실현 결정의 주체(사업부). 개인에게 금액 환산을 떠넘기지 않는다.
- 최소 공통 바닥(팀에 요구하기 전 회사가 까는 인프라)과 과제와 함께 자라는 인프라, "요구는 바닥만큼만", 목표 시트의 전제 조건 칸.
- 투자 없는 AX의 세 가정, 컴퓨트로 풀리는 병목과 아닌 병목, 가장 약한 고리, 적정 투자를 정하는 질문, 역할의 5요소.
- 인터랙티브: 흐름 시뮬레이터, 가치 실현 계산기, 투자 균형 시뮬레이터.
